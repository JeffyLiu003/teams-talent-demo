## L1 业务模型

**系统定位**：信用卡发卡行后台核心系统，覆盖客户 / 账户 / 卡片建档、交易受理、授权审批、日终入账、循环利息、账单支付、报表与用户权限管理。

| 编号 | 业务能力 | 承载程序 |
|---|---|---|
| C1 | 身份鉴别与菜单授权 | COSGN00C、COADM01C、COMEN01C |
| C2 | 用户安全管理 | COUSR00C–03C |
| C4 | 信用卡账户管理 | COACTVWC、COACTUPC |
| C5 | 卡片管理 | COCRDLIC / SLC / UPC |
| C6 | 交易受理与维护 | COTRN00C–02C |
| C7 | 信用卡授权决策 | COPAUA0C |
| C8 | 日终交易入账 | CBTRN02C |

## L2 领域模型

| 实体 | 主键 | 关系 |
|---|---|---|
| Customer | CUST-ID 9(9) | 1:N Card（经 Xref） |
| Account | ACCT-ID 9(11) | 1:N Card、1:N Transaction |
| Card | CARD-NUM X(16) | N:1 Account |
| Transaction | TRAN-ID X(16) | N:1 Account（经卡号） |
| TranCategoryBalance | 账户 + 类型 + 类别 | N:1 Account |
| DisclosureGroup | 组 + 类型 + 类别 | 决定利率 |
| PendingAuthSummary / Detail | 账户 / 授权时间 | 1:N |

**必须保持一致的关键语义**：

1. `ACCT-CURR-BAL` 是欠款余额，不是可用余额。
2. 可用额度 = 信用额度 − 当前余额；有挂起授权汇总时用汇总段的额度 − 信用余额。
3. `TRAN-CAT-BAL` 是按类型 + 类别的累计发生额，不是账户余额。
4. 账单支付交易金额为正数，但扣减余额。
5. 利息按账户汇总后一次性加到余额，并清零本期贷 / 借。

## L3 流程模型（节选）

| 流程 | 步骤 | 跨聚合 |
|---|---|---|
| P5 日终入账 | 读日交易 → 校验卡号（100）→ 账户存在（101）→ 超限（102）→ 到期（103）→ 更新类别余额、账户余额、写交易；失败写拒付明细 | 交易 + 账户 |
| P6 利息计提 | 按类别余额键序遍历 → 查披露组利率（缺失用 `DEFAULT`）→ 利率非 0 时写利息交易 → 账户结算 | 交易 + 账户 |
| P7 账单支付 | 读账户 → 余额 ≤ 0 拒绝 → 用户确认 → 写 `02` / `0002` 交易 → 余额 −= 金额 | **交易 + 账户，需要用例编排** |
| P8 授权决策 | 读 XREF（3100）→ 读账户 / 客户（3100）→ 计算可用额度 → 超额拒绝 4100 → 回写响应 → 更新汇总、写明细 | 授权 |
| P2 账户维护 | 读账户 + 客户 → 校验 → 并发比对 → 分别回写 | **账户 + 客户，拆分时必须拆成两条用例** |

## L4 系统模型

- 在线程序之间全部使用 `XCTL` 跳转，通过 2000 字节 COMMAREA 传递上下文。
- 数据存储：VSAM（账户、卡、交叉引用、客户、交易等 10 个 KSDS）、DB2（交易类型、类别、授权欺诈）、IMS（挂起授权）。
- 外部接口：BMS 终端屏幕、TDQ 报表提交、IBM MQ 授权请求与账户查询。

## L5 实施模型

| 批作业 | 主程序 | 语义 |
|---|---|---|
| POSTTRAN | CBTRN02C | 日终入账 |
| INTCALC | CBACT04C | 日终 / 月结计息 |
| TRANREPT | CBTRN03C | 交易报表 |
| CBPAUP0J | CBPAUP0C | 过期授权清理 |

**迁移必须保留或显式替换的运行约束**：键序分页（卡片每页 7、交易 / 用户每页 10）；`READ UPDATE` + 快照比对的并发控制（新系统改为乐观锁）；批作业失败即终止（新系统改为批量结果 + 拒付明细）。

## 高风险程序

`COPAUA0C`（授权决策）、`CBTRN02C`（入账与额度校验）、`CBACT04C`（利息与余额）、`COBIL00C`（资金扣减）、`COACTUPC`（账户 / 客户资料与额度）。修改其对应的新服务代码时需要额外评审。
