# iCode Talents 演示

纯静态页面，双击 `index.html` 即可在浏览器中打开，不需要网络和本地服务。页面只使用 mock 数据，不读写任何本地文件，也不改动 iCode 配置。

设计说明见 [DESIGN.md](DESIGN.md)。

## 演示脚本（约 15 分钟）

顶栏可以在“管理员端”和“开发者端”之间切换，模拟两台电脑上的两个入口。

**管理员端（张伟）**

1. **来源管理**：点进“信用卡核心系统”，介绍项目中的代码仓和文档集；打开“信用卡核心业务文档”，看来自 Git 仓库、版本记录和“检查更新”。
2. **知识能力**：按四类介绍能力，说明“更新”字段：CodeGraph、文档 RAG 检索、业务知识提取在来源变化后只处理变化的部分。
3. **知识任务**：
   - 新建任务，能力选“会话轨迹诊断”，点“选择会话…”。
   - 在弹窗中让 iCode 筛选“对话轮次超过 50 的会话”，点“全部选中”，再“确定”。
   - 创建并运行，看进度；完成后点“去审阅”。
   - 顺带介绍“当前任务 / 历史”两个页签和按能力筛选。
4. **产物审阅**：
   - 打开“信用卡核心业务知识”（新版本待审阅），切到“对比”，看与线上 v1 的差异（新增营销活动规则）。
   - 在右侧点建议“BR-POST-03 的公式少了‘本期借’……”，iCode 修正后，对比中出现这一行的改动。
   - 点“发布”，交付方式保持“同步到本地”，更新说明已自动填好。
   - 打开“会话轨迹诊断：日终批量入账迁移”，看诊断报告和 Skill 改进建议，然后发布。
   - 回到列表，“银行编码规范要点”提示“提取后文档有变化”。点“重新提取”，新建任务已预填，方式为“更新现有知识”，运行后看日志里读取的变化文件。
   - 打开“card-core-java 开发范式”，看范式总结、代码分析报告和 PR 资料。

**开发者端（李娜）**

5. **项目知识**：
   - “信用卡核心业务知识”显示“有更新”和管理员写的更新说明，点“更新”。
   - 对刚发布的轨迹诊断点“应用”，再点“查看改动”，说明会写到哪里。
   - 用“⋯”菜单演示修改范围和撤销。
6. **本地索引**：为本机的代码仓建立索引，并应用到 iCode。

演示结束后，点顶栏右侧“⋯”中的“重置数据”，恢复初始状态。

## 目录

| 路径 | 内容 |
|---|---|
| `index.html`、`css/`、`js/` | 页面。`js/data.js` 是 mock 数据，`js/knowledge.js` 处理产物版本、对比和应用改动，`js/pages/` 下每个文件对应一个页面 |
| `content/` | 产物与 Skill 的原文（业务知识、开发范式、三份轨迹诊断报告、配套 Skill） |
| `js/content.js` | 由 `content/` 生成，页面预览产物时使用 |
| `tools/bundle-content.mjs` | 修改 `content/` 后运行 `node tools/bundle-content.mjs`，重新生成 `js/content.js` |
| `vendor/marked.umd.js` | Markdown 渲染（marked v18.0.11） |
