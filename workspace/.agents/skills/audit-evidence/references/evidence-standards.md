# 审计证据标准

本标准定义银行软件交付过程中审计证据的类型、格式要求、保存期限与合规要求。所有审计证据包须符合本标准。适用于 L2 标准档与 L3 实施级。

## 1. 证据类型

### 1.1 按工件类型分类

| 证据类型 | 来源平台 | 必填档位 | 说明 |
|---------|---------|---------|------|
| 需求证据 | 需求平台 | L2+ | 需求说明书 + 评审记录 + 业务规则溯源 |
| 设计证据 | 设计平台/Confluence | L2+ | 设计文档 + 评审记录（含架构/接口/数据设计） |
| 故事证据 | 敏捷平台 | L2+ | 用户故事 + 验收标准 + 迭代归属 |
| 代码变更证据 | Git 平台 | L2+ | MR + 评审记录 + CI/CD 结果 |
| 测试证据 | 测试平台 | L2+ | 测试用例 + 执行报告 + 缺陷清单 |
| 变更证据 | 变更管理平台 | L2+ | 变更单 + 审批记录 + 回滚预案 |
| 发布证据 | 发布平台 | L2+ | 发布单 + 灰度记录 + 回滚记录 |
| 复盘证据 | PIR 平台/Confluence | L2+ | 事后复盘报告 + 改进项跟踪 |
| 监控证据 | 监控平台 | L3 | 发布前后监控指标对比（可选） |
| 日志证据 | 日志平台 | L3 | 关键操作日志（可选） |

### 1.2 按证据属性分类

| 属性 | 说明 | 必填档位 |
|------|------|---------|
| 原始证据 | 平台直接导出的工件（含时间戳与责任人） | L2+ |
| 替代证据 | 原工件丢失或不可达时提供的替代（归档副本/平台快照/人工说明） | L3（仅当原证据缺失时） |
| 补强证据 | 用于补充说明的附加证据（如监控截图、日志导出） | L3（可选） |

## 2. 格式要求

### 2.1 证据包格式

| 格式 | 用途 | 说明 |
|------|------|------|
| Markdown | 人类可读，评审与归档 | 按 `templates/evidence-pack.md` 模板生成 |
| JSON | 机器可读，门禁自动化消费 | 结构 `{"chain": [{"stage", "id", "url"}, ...]}` |

### 2.2 工件链接要求

- 链接须直达工件详情页（非列表页/首页）
- 链接须为 https（内网可例外，但须说明）
- 链接须在审计窗口内可达（失效链接须提供替代证据）
- 链接须包含工件 ID（URL 路径中含 ID 段）

### 2.3 时间戳要求

- 时间戳精确到日期（YYYY-MM-DD），关键节点精确到秒（YYYY-MM-DD HH:MM:SS）
- 时间戳取工件的关键节点（创建/评审/合并/执行），非当前时间
- 时间戳须为平台记录的原始时间，不得人工修改

### 2.4 责任人要求

- 责任人须为个人（姓名 + 工号），不得仅填团队名
- 每个环节至少一名责任人
- 发布环节须含发布负责人 + 值班 SRE
- 变更环节须含变更申请人 + 变更审批人

## 3. 保存期限

### 3.1 监管要求保存期限

| 证据类型 | 最短保存期限 | 依据 |
|---------|------------|------|
| 反洗钱相关交易记录 | 5 年 | 《反洗钱法》第十九条 |
| 客户身份资料 | 5 年（业务关系结束后） | 《反洗钱法》第十九条 |
| 大额/可疑交易报告 | 5 年 | 《金融机构大额交易和可疑交易报告管理办法》 |
| 支付交易记录 | 5 年 | 《电子支付指引》 |
| 业务系统日志 | 6 个月以上 | 《网络安全法》第二十一条 |
| 个人信息处理记录 | 3 年 | 《个人信息保护法》第五十六条 |

### 3.2 行内制度保存期限

| 证据类型 | 最短保存期限 | 依据 |
|---------|------------|------|
| 需求说明书 | 系统全生命周期 + 5 年 | 行内需求管理办法 |
| 设计文档 | 系统全生命周期 + 5 年 | 行内设计管理办法 |
| 测试报告 | 发布后 5 年 | 行内测试管理办法 |
| 变更单 | 发布后 5 年 | 行内变更管理办法 |
| 发布记录 | 发布后 5 年 | 行内发布管理办法 |
| PIR 报告 | 发布后 5 年 | 行内事故管理办法 |
| 审计证据包 | 审计完成后 5 年 | 行内审计管理办法 |

> 取最严格的保存期限。涉及监管报送的证据保存期限不少于监管要求。

## 4. 合规要求

### 4.1 证据完整性

- 全链路 ID 可追溯（REQ → US → MR → TC → CHG → REL → PIR）
- 缺失项有原因说明（不适用 / 暂缺 / 替代证据 / 已丢失）
- 失效链接有替代证据（L3）
- 证据包可独立举证（不依赖口头说明）

### 4.2 证据真实性

- 工件须为平台原始记录，不得人工篡改
- 证据包生成后不得修改（仅追加版本）
- 证据包哈希值须上链或哈希存证（监管要求场景）
- 替代证据须经合规与阶段负责人共同确认

### 4.3 证据保密性

- 涉及客户信息的证据须脱敏（展示时脱敏，存储时加密）
- 涉及生产数据的证据须按数据分类分级管理
- 证据包访问须有权限控制（最小授权原则）
- 跨境传输证据须经安全评估（如涉及）

### 4.4 证据可审计性

- 证据包生成、修改、访问须有审计日志
- 证据包版本须可追溯（不覆盖，仅追加）
- 证据包归档须有时间戳与操作人记录
- 证据包销毁须经审批并记录（保存期满后）

## 5. 档位要求汇总

| 要求 | L1 草稿 | L2 标准 | L3 实施级 |
|------|---------|---------|----------|
| 工件清单 | 可选 | 必填 | 必填 |
| ID 链完整性 | 可选 | 必填 | 必填（100%） |
| 链接有效性 | 不校验 | 必填 | 必填（100%或有替代证据） |
| 缺失原因 | 不要求 | 必填 | 必填（分类+影响评估） |
| 替代证据 | 不要求 | 失效时提供 | 失效时提供（经双签确认） |
| 全链路 ID 矩阵 | 不要求 | 不要求 | 必填 |
| 追溯索引 | 不要求 | 不要求 | 必填（双向） |
| 合规确认 | 不要求 | 必填 | 必填（双签） |
| 证据包哈希存证 | 不要求 | 不要求 | 监管要求场景必填 |

## 6. 监管引用规范

在证据包中引用监管要求时，须使用标准格式：

```
[监管文号] 条款编号 条款摘要
```

示例：
- `[《反洗钱法》] 第十九条 金融机构应当按照规定建立客户身份资料和交易记录保存制度。客户身份资料在业务关系结束后至少保存五年，客户交易信息自交易结束之日起至少保存五年。`
- `[《个人信息保护法》] 第五十一条 处理者应当对个人信息采取加密、去标识化等安全技术措施。`
- `[央行令〔2018〕第2号] 第八条 金融机构应当在大额交易发生之日起5个工作日内报送。`

## 7. 失效证据处理流程

1. 发现失效链接或缺失工件时，记录失效原因（404/403/超时/平台迁移/已删除）
2. 评估缺失对审计结论的影响（资金安全/监管报送/业务连续性）
3. 提供替代证据（归档副本/平台快照/人工说明）
4. 替代证据经合规与阶段负责人共同确认（双签）
5. 在证据包"缺失原因详表"与"替代证据登记"章节中记录
6. L3 场景须在"证据链接有效性验证"章节中标注替代证据覆盖率

## 8. 证据包版本管理

| 版本类型 | 触发条件 | 处理方式 |
|---------|---------|---------|
| 初始版本 | 首次生成证据包 | v1.0 |
| 修订版本 | 补充缺失工件或修正错误 | v1.1, v1.2, ... |
| 重大修订 | 审计范围变更或档位调整 | v2.0 |
| 归档版本 | 审计完成归档 | vFinal + 哈希存证 |

> 修订须保留历史版本，不得覆盖。每个版本须记录修订原因、修订人、修订时间。
