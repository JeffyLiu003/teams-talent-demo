# scripts/ — 产出脱敏技能脚本

本目录包含 `output-sanitization` 技能的确定性校验脚本。所有脚本遵循统一接口规范：CLI 调用、JSON 输出、退出码表示结果。

## 脚本清单

| 脚本 | 用途 | 退出码 |
|------|------|--------|
| `sanitize.py` | 敏感信息扫描与脱敏（手机号/身份证/密钥，密钥命中即阻断） | 0/2/3 |
| `pii_scanner.py` | PII 识别与统计（手机号/身份证/银行卡号/邮箱） | 0/1/3 |

## sanitize.py

### 用途
扫描产出文本中的敏感信息（手机号/身份证/密钥），就地脱敏并输出脱敏报告。命中密钥类时直接阻断（`blocked=true`，退出码=2），防止密钥进入评审或对外渠道。支持将脱敏后文本写入输出文件。

### 接口
```
python sanitize.py <input_file> [--output 输出文件] [--json]
```

### 参数
| 参数 | 说明 |
|------|------|
| `input_file` | 输入文件路径（.md / .txt / 任意文本文件） |
| `--output` | 脱敏后文本输出文件路径（可选）。未指定时仅输出报告，不写脱敏文件 |
| `--json` | 输出 JSON 格式（当前实现始终输出 JSON，此参数为接口预留） |

### 退出码
| 码 | 含义 |
|----|------|
| 0 | 通过（无密钥命中，未阻断） |
| 2 | 阻断（命中密钥类，`blocked=true`，须人工核查后才能提交） |
| 3 | 参数错误（文件不存在 / 读取失败） |

> 退出码优先级：阻断（2） > 通过（0）。即只要命中密钥即返回 2，无论是否同时命中手机号/身份证。

### 检查项
1. **手机号检测与掩码**：正则 `1[3-9]\d{9}`，脱敏为 `前3位+****+后4位`（如 `138****5678`）
2. **身份证检测与掩码**：正则 `\d{17}[\dXx]`，脱敏为 `前6位+********+后4位`
3. **密钥检测与阻断**：正则 `(AKIA[0-9A-Z]{16}|sk-[A-Za-z0-9]{20,})`，替换为 `***REDACTED***`，同时置 `blocked=true` 并返回退出码 2
4. **脱敏后文本输出**：指定 `--output` 时，将脱敏后文本写入输出文件；未指定时仅输出报告

### 内置模式
| 类型 | 正则 | 处置 | 阻断 |
|------|------|------|------|
| 手机号 | `1[3-9]\d{9}` | 掩码（前3+****+后4） | 否 |
| 身份证 | `\d{17}[\dXx]` | 掩码（前6+********+后4） | 否 |
| 密钥 | `AKIA[0-9A-Z]{16}` / `sk-[A-Za-z0-9]{20,}` | 替换为 `***REDACTED***` | 是 |

### JSON 输出示例
```json
{
  "hits": {"手机号": 1, "身份证": 0, "密钥": 1},
  "blocked": true
}
```

### 调用示例
```bash
# 基本扫描（仅报告，不写脱敏文件）
python skills/output-sanitization/scripts/sanitize.py 产出文档.md --json

# 扫描并写脱敏后文件
python skills/output-sanitization/scripts/sanitize.py 产出文档.md --output 脱敏后.md --json

# 管道消费（退出码驱动 CI 门禁：exit=2 阻断提交）
python skills/output-sanitization/scripts/sanitize.py 产出文档.md && echo "脱敏通过" || echo "高危命中已阻断，请核查"
```

### 单测对应
`tests/test_scripts.py` 中 `output-sanitization/sanitize.py` 条目（3 用例）：
- `secret_blocked`：含密钥 `sk-testsecret1234567890` → exit=2，输出含 `blocked`
- `phone_masked`：含手机号 `13812345678` → exit=0，输出含 `blocked`
- `missing_file`：文件不存在 → exit=3，输出含 `error`

## pii_scanner.py

### 用途
扫描产出文本中的个人敏感信息（PII），按类型统计命中数量。仅识别统计不脱敏，用于产出提交前的 PII 召回率评估与合规检查。

### 接口
```
python pii_scanner.py <input_file> [--json]
```

### 参数
| 参数 | 说明 |
|------|------|
| `input_file` | 输入文件路径（.md / .txt / 任意文本文件） |
| `--json` | 输出 JSON 格式（当前实现始终输出 JSON，此参数为接口预留） |

### 退出码
| 码 | 含义 |
|----|------|
| 0 | 通过（未发现 PII） |
| 1 | 告警（发现 PII，须脱敏处理后重跑） |
| 3 | 参数错误（文件不存在 / 读取失败） |

### 检查项
1. **手机号检测**：正则 `1[3-9]\d{9}`
2. **身份证检测**：正则 `\d{17}[\dXx]`
3. **银行卡号检测**：正则 `\d{16,19}`（16-19 位连续数字）
4. **邮箱检测**：正则 `[\w.\-]+@[\w\-]+\.[\w.]+`
5. **命中统计**：按类型统计命中数，输出总数

### 内置模式
| 类型 | 正则 | 说明 |
|------|------|------|
| 手机号 | `1[3-9]\d{9}` | 11 位中国大陆手机号 |
| 身份证 | `\d{17}[\dXx]` | 18 位身份证号（末位可为 X） |
| 银行卡号 | `\d{16,19}` | 16-19 位连续数字（含误报可能，须人工复核） |
| 邮箱 | `[\w.\-]+@[\w\-]+\.[\w.]+` | 标准邮箱格式 |

### JSON 输出示例
```json
{
  "pii_found": {"手机号": 2, "身份证": 0, "银行卡号": 1, "邮箱": 1},
  "total": 4
}
```

### 调用示例
```bash
# PII 识别（统计不脱敏）
python skills/output-sanitization/scripts/pii_scanner.py 产出文档.md --json

# 管道消费（退出码驱动 CI 门禁：exit=1 须脱敏后重跑）
python skills/output-sanitization/scripts/pii_scanner.py 产出文档.md && echo "无 PII" || echo "发现 PII，须脱敏"
```

### 特殊处理
- 银行卡号正则 `\d{16,19}` 会匹配 16-19 位连续数字，可能误报非银行卡的长数字串（如订单号/流水号）。命中后须人工复核
- 脚本仅统计不脱敏，脱敏处置须由 `sanitize.py` 或 Agent 按模式清单执行

### 单测对应
`tests/test_scripts.py` 中 `output-sanitization/pii_scanner.py` 条目（3 用例）：
- `pii_found`：含手机号 `13812345678` → exit=1，输出含 `pii_found`
- `clean_text`：无敏感信息 → exit=0，输出含 `total`
- `missing_file`：文件不存在 → exit=3，输出含 `error`

## 能力边界与 L3 期望

> 以下为当前脚本能力边界与 L3 实施级期望能力的差异说明。**当前脚本接口不做变更**，L3 能力由 Agent 在报告层与流程层补充。

### 当前能力边界
| 能力 | sanitize.py | pii_scanner.py | 说明 |
|------|-------------|----------------|------|
| 内置模式 | 手机号/身份证/密钥（3类） | 手机号/身份证/银行卡号/邮箱（4类） | 覆盖常见银行场景核心类型 |
| 白名单 | 不支持 | 不支持 | 测试数据/示例值会被误脱敏 |
| 外部模式整合 | 不支持 | 不支持 | 无法加载 `templates/sensitive-data-patterns.md` 的扩展模式 |
| 误脱敏统计 | 不支持 | 不支持 | 无白名单命中数与误脱敏标记 |
| 阻断审计日志 | 不支持 | 不支持 | 仅输出 JSON 报告，不记录操作人/时间 |
| 生产数据片段检测 | 不支持 | 不支持 | 仅检测密钥类阻断，未覆盖生产数据片段 |
| 脱敏不可逆验证 | 不支持 | 不支持 | 不做还原测试 |

### L3 期望能力（由 Agent 报告层补充）
| L3 期望能力 | 当前替代方案 |
|------------|-------------|
| 白名单管理 | Agent 在 `templates/sanitization-report.md` 的"白名单命中统计"字段手工维护白名单与命中数 |
| 误脱敏统计 | Agent 在报告的"误脱敏标记"字段记录误脱敏案例，按月复盘 |
| 阻断审计日志 | Agent 在报告的"阻断记录"字段补充操作人/时间/处置，纳入安全审计 |
| 生产数据片段检测 | Agent 按 `templates/sensitive-data-patterns.md` 的生产数据模式手工检测并标记 |
| 脱敏不可逆验证 | Agent 对掩码类脱敏做还原测试，在报告的"脱敏不可逆验证"字段记录结论 |
| 外部模式整合 | Agent 参照 `templates/sensitive-data-patterns.md` 扩展模式，在报告层覆盖更多类型 |

> L3 场景的白名单规则与误脱敏处置须由安全与合规共同确认；Agent 起草，安全确认后定稿。
