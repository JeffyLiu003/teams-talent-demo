# 数据分类分级

> 本资料定义银行场景下的数据分类分级标准，指导 Agent 产出的脱敏处置。所有 Agent 产出提交前必须按本标准做脱敏扫描。
>
> 分级依据：《个人金融信息保护技术规范》（JR/T 0171-2020）、《数据安全法》、《个人信息保护法》、行内数据分类分级管理办法。

## 一、数据分级总览

| 级别 | 命名 | 处置原则 | 阻断规则 |
|------|------|---------|---------|
| L5 | 绝密 | 禁止任何形式输出，命中即阻断 | 阻断 |
| L4 | 机密 | 禁止明文输出，须替换/删除，命中即阻断 | 阻断 |
| L3 | 敏感 | 须脱敏后输出（掩码/替换），不可明文 | 不阻断（须脱敏） |
| L2 | 内部 | 限内部使用，按场景脱敏 | 不阻断 |
| L1 | 公开 | 可公开，无需脱敏 | 不阻断 |

## 二、各级数据详解

### L5 绝密

| 字段 | 内容 |
|------|------|
| 数据示例 | 核心算法源码、支付系统密钥主密钥、央行报送前置机配置、核心账务系统root凭证 |
| 脱敏规则 | 禁止任何形式输出；命中即删除并阻断；须追溯来源并轮换 |
| 处置要求 | 命中即阻断提交（exit=2）；须报告安全团队；凭证类须立即轮换 |
| 合规依据 | 《数据安全法》第27条核心数据保护；《网络安全法》关键信息基础设施保护 |

### L4 机密

| 字段 | 内容 |
|------|------|
| 数据示例 | AWS AKIA 密钥、OpenAI sk- 密钥、PEM 私钥、JWT Token、数据库连接串、生产数据库导出、生产日志片段、信用卡 CVV |
| 脱敏规则 | 替换为 `***REDACTED***` 或整段删除；命中即阻断提交 |
| 处置要求 | 命中即阻断提交（exit=2）；须人工核查是否为真实凭证；真实凭证须轮换 |
| 合规依据 | 《数据安全法》第27条重要数据保护；行内密钥管理办法；行内生产数据管理办法 |

### L3 敏感

| 字段 | 内容 |
|------|------|
| 数据示例 | 手机号、身份证号、银行卡号、护照号、港澳通行证、社保号、纳税人识别号、内网IP、生产环境标识 |
| 脱敏规则 | 掩码处理（保留部分字符，其余替换为*）；脱敏不可逆；格式保持合理 |
| 处置要求 | 须脱敏后输出；脱敏后须验证不可逆；不阻断提交但须记录命中统计 |
| 合规依据 | 《个人信息保护法》第51条个人信息安全保护；《个人金融信息保护技术规范》（JR/T 0171-2020）C2/C3级；行内客户信息保护办法 |

### L2 内部

| 字段 | 内容 |
|------|------|
| 数据示例 | 邮箱、姓名、地址、工号/员工号、车牌号、MAC地址、监控指标导出、交易金额、账户余额 |
| 脱敏规则 | 按场景脱敏；内部文档可保留，对外输出须掩码 |
| 处置要求 | 内部使用可保留；对外输出须脱敏；不阻断提交 |
| 合规依据 | 行内数据分类分级管理办法；行内信息对外发布管理办法 |

### L1 公开

| 字段 | 内容 |
|------|------|
| 数据示例 | 脱敏后的统计数据、产品宣传材料、公开披露的年报数据、官网公告 |
| 脱敏规则 | 无需脱敏；可公开输出 |
| 处置要求 | 无需脱敏；确认无敏感信息残留后可对外输出 |
| 合规依据 | 《政府信息公开条例》；行内信息公开管理办法 |

## 三、脱敏处置方式对照

| 处置方式 | 适用级别 | 示例 | 不可逆 |
|---------|---------|------|--------|
| 替换 | L4/L5 | 密钥 → `***REDACTED***` | 是 |
| 删除 | L4/L5 | 生产数据片段 → 整段移除 | 是 |
| 掩码 | L3 | 手机号 `13812345678` → `138****5678` | 是 |
| 掩码 | L2 | 邮箱 `zhang@bank.com` → `z***@bank.com` | 是 |
| 保留 | L1 | 脱敏后统计数据原样保留 | - |

> 掩码字符数须 ≥ 原值 50%，确保不可逆。脱敏后须验证格式合理（保留可识别结构）且不可逆（无法从掩码还原原值）。

## 四、银行场景常见数据类型速查

| 业务场景 | 涉及数据类型 | 分级 | 处置 |
|---------|------------|------|------|
| 客户开户 | 姓名/身份证/手机号/地址 | L3/L2 | 掩码 |
| 转账交易 | 账号/姓名/金额 | L3/L2 | 掩码 |
| 信用卡业务 | 卡号/CVV/有效期 | L3/L4 | 掩码/删除 |
| 系统运维 | IP/主机名/密钥/连接串 | L2/L4 | 掩码/替换 |
| 数据分析 | 客户明细/交易明细 | L3 | 掩码 |
| 生产排障 | 生产日志/数据库导出 | L4 | 删除/替换 |
| 监管报送 | 客户身份/交易数据 | L3 | 掩码（按报送要求） |
| 对外披露 | 统计数据/产品材料 | L1 | 保留 |

## 五、合规依据索引

| 法规/标准 | 适用范围 | 重点条款 |
|---------|---------|---------|
| 《数据安全法》 | 全行数据 | 第21条分类分级、第27条核心数据保护、第31条重要数据保护 |
| 《个人信息保护法》 | 个人信息 | 第28条敏感个人信息、第51条安全保护措施 |
| 《网络安全法》 | 网络数据 | 第21条安全保护义务、第31条关键信息基础设施 |
| JR/T 0171-2020 | 个人金融信息 | C1/C2/C3分级、生命周期保护要求 |
| 《非银行支付机构条例》 | 支付业务 | 客户信息保护、备付金管理 |
| 行内数据分类分级管理办法 | 全行数据 | 分级标准、处置要求、审批流程 |
| 行内客户信息保护办法 | 客户信息 | 收集/存储/使用/传输/销毁全链路保护 |
| 行内密钥管理办法 | 密钥管理 | 密钥生成/存储/使用/轮换/销毁 |

> 所有 Agent 产出提交前必须过脱敏扫描（`scripts/sanitize.py` + `scripts/pii_scanner.py`）；L4/L5 数据命中即阻断，L3 数据须脱敏后输出。

## 六、L3 必填深度字段

| 字段 | 要求 | 示例 |
|------|------|------|
| 分级覆盖度 | 覆盖 L1-L5 五级 + 银行场景常见类型 | 本资料覆盖 5 级 8 场景 |
| 脱敏规则 | 每级标注处置方式与不可逆性 | L4 替换/删除（不可逆），L3 掩码（不可逆） |
| 处置要求 | 每级标注阻断规则与处置流程 | L4/L5 阻断，L3 脱敏后输出 |
| 合规依据 | 每级标注法规/标准/行内制度 | 《数据安全法》第27条、JR/T 0171-2020 |
| 场景速查 | 银行业务场景与数据类型对照 | 客户开户/转账/信用卡/运维等 8 场景 |
