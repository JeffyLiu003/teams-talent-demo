# scripts/ — 变更申请单（RFC）技能脚本

本目录包含 `change-rfc` 技能的确定性校验脚本。所有脚本遵循统一接口规范：CLI 调用、JSON 输出、退出码表示结果。

## 脚本清单

| 脚本 | 用途 | 退出码 |
|------|------|--------|
| `rfc_validate.py` | RFC必填字段校验：扫描RFC文档文本，比对十项必填字段关键词是否出现 | 0/2/3 |

---

## rfc_validate.py

### 用途
校验RFC（变更申请单）文档的必填字段完整性。读取RFC Markdown 文档全文，逐项比对十项必填字段关键词是否作为子串出现。任一字段未命中即视为校验失败。

### 接口
```
python rfc_validate.py <rfc_md> [--json]
```

### 参数
| 参数 | 说明 |
|------|------|
| `rfc_md` | RFC文档路径（.md），须含十项必填字段关键词 |
| `--json` | 显式声明 JSON 输出（默认即为 JSON，效果相同） |

### 退出码
| 码 | 含义 |
|----|------|
| 0 | 全部通过（十项必填字段全部命中） |
| 2 | 失败（存在缺失字段，`missing` 列表非空） |
| 3 | 参数错误（文件不存在 / 无法读取） |

> 退出码优先级：缺失字段（2）> 通过（0）。脚本未定义退出码 1（警告）。

### 检查项
1. **文件读取**：读取 `rfc_md` 全文。文件不存在或不可读时返回 exit=3。
2. **必填字段匹配**：将 `REQUIRED` 列表中每个关键词作为子串在全文中查找。`REQUIRED = ["RFC编号", "变更类型", "变更原因", "变更范围", "影响分析", "测试退出", "发布计划", "回滚方案", "建议窗口", "干系人"]`。
3. **缺失清单**：未命中的关键词汇总为 `missing` 列表。
4. **完整性判定**：`missing` 为空 → `complete=true`、exit=0；否则 `complete=false`、exit=2。

### 必填字段清单
| 序号 | 字段关键词 | 说明 |
|------|----------|------|
| 1 | `RFC编号` | RFC唯一标识 |
| 2 | `变更类型` | 正常/紧急/标准 |
| 3 | `变更原因` | 业务/技术/合规驱动 |
| 4 | `变更范围` | 受影响模块/系统 |
| 5 | `影响分析` | 引用影响分析报告 |
| 6 | `测试退出` | 引用测试退出报告 |
| 7 | `发布计划` | 引用发布计划 |
| 8 | `回滚方案` | 回滚步骤与时长 |
| 9 | `建议窗口` | 变更窗口起止 |
| 10 | `干系人` | 变更/审批/通知人员 |

### 字段匹配规则
- 匹配方式：子串包含（`keyword in document_text`）
- 仅检查关键词出现，不解析字段值有效性（如"建议窗口"出现即通过，不校验窗口格式）
- 不校验证据链接可访问性（L3 深度要求须人工或额外脚本完成）
- `FROZEN_DAYS` 变量当前为空列表且未参与逻辑，监管冻结期校验须人工或额外脚本完成

### JSON 输出示例
通过时输出：
```json
{
  "missing": [],
  "complete": true
}
```

存在缺失字段时输出：
```json
{
  "missing": ["测试退出", "回滚方案"],
  "complete": false
}
```

参数错误时输出：
```json
{
  "error": "[Errno 2] No such file or directory: '...'"
}
```

### 调用示例
```bash
# 基本校验
python skills/change-rfc/scripts/rfc_validate.py ./RFC-001.md

# JSON 输出（供 Agent 消费）
python skills/change-rfc/scripts/rfc_validate.py ./RFC-001.md --json

# CI 门禁（退出码驱动）
python skills/change-rfc/scripts/rfc_validate.py ./RFC-001.md && echo "RFC字段完整" || echo "RFC字段缺失"

# RFC-001.md 示例
# # RFC-001 限额参数调整
# RFC编号 RFC-001
# 变更类型 正常
# 变更原因 监管要求调整日累计限额上限
# 变更范围 限额服务/参数中心
# 影响分析 见 IA-2026-008
# 测试退出 见 TR-2026-008
# 发布计划 见 RP-2026-008
# 回滚方案 见 RB-2026-008（步骤5步，时长上限30分钟）
# 建议窗口 2026-08-20 22:00-23:30
# 干系人 张三/李四/王五
```

### 能力边界
- 仅校验字段关键词出现，不解析字段值格式、有效性、可访问性
- 不校验证据链接是否指向有效工单（L3 深度要求须人工或额外脚本完成）
- 不校验窗口冲突（`FROZEN_DAYS` 当前为空且未参与逻辑），窗口冲突须配合 `window_scheduler.py`
- 不校验变更分级与分级依据（L3 深度要求须人工或额外脚本完成）
- 不校验回滚方案量化字段（步骤数/时长上限/演练证据）
- 不识别字段值的语义（如"变更类型"后接任意文本均通过）

### 单测对应
`tests/test_scripts.py` 中 `change-rfc/rfc_validate.py` 条目（3 用例）：
- `complete_rfc`：RFC含全部十项字段 → exit=0，输出含 `complete`
- `incomplete_rfc`：RFC仅含"RFC编号" → exit=2，输出含 `missing`
- `missing_file`：文件不存在 → exit=3，输出含 `error`
