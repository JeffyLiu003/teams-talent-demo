# SoD 合规策略

本文件定义银行软件研发与运维全流程中职责分离（Segregation of Duties, SoD）的合规策略，包括职责分离原则、角色定义、权限分配规则与冲突处置流程。作为 `sod-compliance-check` 技能的制度依据。

## 1. 职责分离原则

### 1.1 四眼原则

银行所有涉及资金、生产数据、监管报送的操作须遵循四眼原则：**执行、审批、复核、审计** 四类职责相互独立，不得由同一角色或同一人员兼任。

| 职责 | 说明 | 典型权限 |
|------|------|---------|
| 执行 | 实际完成操作（编码、配置、发布） | 编码、参数配置、生产发布 |
| 审批 | 对执行结果或申请进行批准 | 批准MR、参数审批、变更审批 |
| 复核 | 对执行过程进行二次校验 | 代码评审、交易复核、测试 |
| 审计 | 对全流程进行独立审查 | 审计读取、日志审计、数据导出 |

### 1.2 互斥原则

下列职责对天然互斥，不得由同一角色同时承担：
- 执行 ↔ 审批（自己批自己）
- 执行 ↔ 复核（自己审自己）
- 执行 ↔ 审计（既当运动员又当裁判）
- 修改 ↔ 审计（篡改被审计数据）

### 1.3 最小权限原则

每个角色仅授予完成其职责所必需的最小权限集合，禁止权限过度聚合。权限分配须可追溯到业务必要性。

## 3. 权限分配规则

### 3.1 角色定义规则

- 角色名使用英文标识（Dev/Reviewer/Approver 等），禁止中文口语化别名（"开发""测试""审批人"）
- 每个角色须有明确的职责描述与权限清单
- 角色新增/变更须经合规审批，同步更新标准角色目录

### 3.2 权限分配规则

- 权限名使用标准术语（编码/代码评审/批准MR/参数配置 等），与 `references/sod-matrix.md` 对齐
- 单个角色的权限集不得包含冲突矩阵中的互斥权限对（直接冲突）
- 用户可持有多角色，但累积权限集不得命中冲突对（间接冲突，L3 检测）
- 权限分配须记录审批链：申请人/审批人/生效时间

### 3.3 权限回收规则

- 角色变更时，原权限须即时回收
- 离职/转岗人员权限须在 24h 内回收
- 权限回收须记录变更审计（变更人/时间/前后值）

## 4. 冲突处置流程

### 4.1 冲突分级

| 等级 | 判定标准 | 处置时效 |
|------|---------|---------|
| 高 | 涉及资金安全、监管报送、生产数据、密钥管理的直接冲突 | 即时阻断 |
| 中 | 涉及流程绕过、间接冲突（传递闭包） | 24h 内 |
| 低 | 涉及操作规范、文档完整性 | 下次审计前 |

### 4.2 处置动作

| 处置动作 | 适用场景 | 说明 |
|---------|---------|------|
| 分离权限 | 直接冲突，高风险 | 将互斥权限拆分至不同角色 |
| 转授角色 | 用户多角色间接冲突 | 将冲突角色转授他人 |
| 补偿控制 | 无法立即分离的中低风险 | 增设复核/审计/告警作为补偿 |
| 登记备案 | 低风险，可接受残留 | 记录风险并定期复核 |

### 4.3 处置流程

1. **检出**：`sod_check.py` 检出直接冲突；L3 算法检出间接冲突
2. **定级**：按冲突矩阵风险等级与场景判定高/中/低
3. **处置**：按处置动作表执行，高风险即时阻断流程
4. **验证**：重跑 `sod_check.py` 确认冲突已清零
5. **审计**：记录角色权限变更审计，含变更人/时间/前后值/审批链
6. **归档**：合规与安全负责人签字归档，L3 须共同确认

## 5. 检查档位与触发条件

| 档位 | 触发条件 | 检查范围 | 审批要求 |
|------|---------|---------|---------|
| L1 草稿 | 内部权限对齐、非正式检查 | 直接冲突 | 无需评审 |
| L2 标准 | 常规门禁评审、配置变更 | 直接冲突 + 门禁执行人/审批人 | 合规确认 + 安全负责人签字 |
| L3 实施级 | 资金安全/监管报送/跨系统集成/首次上线/高风险变更 | 直接 + 间接（传递闭包）+ 变更审计 | ARB/合规评审 + 深度门禁全通过 |

### 自动升 L3 场景

涉及以下场景的 SoD 冲突检查自动从 L2 升 L3：
- 反洗钱相关权限冲突
- 限额参数配置与审批冲突
- 客户资金操作权限冲突
- 监管报送权限冲突
- 跨行接口权限冲突
- 生产数据变更权限冲突

## 6. 合规依据

| 依据 | 适用范围 |
|------|---------|
| 《商业银行内部控制指引》 | 四眼原则、职责分离 |
| 央行令〔2018〕第2号《金融机构大额交易报告管理办法》 | 反洗钱报送与审核分离 |
| 《反洗钱法》第十九条 | 交易记录保存≥5年不可篡改 |
| 《数据安全法》第二十一条 | 数据分类分级与访问控制 |
| 《个人信息保护法》第五十一条 | 个人信息脱敏与访问控制 |
| 行内变更管理规程 | 变更申请与发布分离 |
| 行内代码管理规定 | 编码与评审分离 |
| 行内密钥管理办法 | 密钥三分离原则 |

## 7. 维护与校订

- 本策略按季度校订，由合规与安全负责人共同签字归档
- 标准角色目录与权限清单随组织架构调整同步更新
- 冲突处置流程的变更须经 ARB 评审
- 版本化管理，历史版本可追溯

> 本策略是 `sod-compliance-check` 技能的制度依据。`references/sod-matrix.md` 中的冲突对与本策略的角色定义、权限分配规则对齐。
